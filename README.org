#+TITLE: SEM Assistant (Elisp Daemon)

* Overview
SEM Assistant is a self-hosted Emacs daemon for single-user personal operations.
It receives mobile captures via WebDAV, routes them through deterministic Elisp
flows, uses remote LLM calls for bounded text transformations, and writes results
to your Org files. In practice, it handles four main loops: inbox processing,
URL-to-org-roam capture, a morning day plan, and periodic git sync for org-roam
notes.

* Motivation
The core idea is simple: capture fast on mobile, process safely on a remote box,
and keep the output in plain Org files you own.

This project intentionally treats the LLM as a tool, not as the orchestrator.
The orchestration lives in Elisp code with explicit routing, retries, logging,
and file contracts. This is the key conceptual difference from systems where the
LLM directly drives workflow decisions end-to-end. Here, the model helps with
normalization, planning text, and summarization, but the daemon controls the
pipeline.

* How to use
** Hardcoded flows and tags
- Inbox source is =/data/tasks/inbox-mobile.org=.
- Headline tagged =:task:= is routed to task normalization + planning flow.
- Headline tagged =:link:= is routed to URL capture flow.
- Headline title that starts with =http://= or =https://= is treated as link
  capture even without =:link:=.
- Unknown headline types are skipped and logged.

** Daily plan
- Every day at 07:00 the daemon schedules the day directly in
  =/data/tasks/tasks.org=; there is no separate plan file.
- Input: overdue tasks, tasks scheduled today without a time, deadlines within
  7 days and the unscheduled backlog, plus =rules.org=.  Timed tasks of today
  and today's occurrences of recurring tasks from =rec-tasks.org= are busy
  slots and are never modified.
- Every overdue task gets a time block today, a new date, or (when it looks
  obsolete) loses its SCHEDULED and gets the =:drop_suggested:= tag.  Free time
  is then filled from deadlines and backlog.  DEADLINE timestamps are never
  changed; each changed task gets a =:SEM_DAILY_PLAN: <date> <action>= property.
- The LLM only returns =PLAN/DEFER/DROP= lines; the daemon validates them (no
  overlaps, nothing in the past) and edits only planning lines.
- Write safety: the new content goes to a temp file, then =tasks.org= is
  re-hashed; it is replaced only if unchanged since it was read.  Otherwise
  the run restarts from fresh content (new LLM call, up to 3 attempts).  The
  previous version is kept in =/data/.tasks-backups/= for 14 days.
- If the LLM call fails, =tasks.org= is left untouched.
- Manual trigger:
  #+begin_src sh
  docker compose exec emacs emacsclient -s sem-server -e "(sem-daily-plan-generate)"
  #+end_src

** Scheduling rules
=/data/tasks/rules.org= is free text passed to task normalization, the planner and
the daily plan. Concrete rules work best, for example working hours, days off,
per-category windows ("family tasks after 18:00"), a daily workload limit, and
which kinds of tasks to batch together.

** Task format
Generated tasks carry their category as a real headline tag (=:work:= etc.),
an =:EFFORT:= estimate, and SCHEDULED/DEADLINE on the line directly below the
headline, the only place Org agenda and org-element recognize them. Tasks
written by older versions had SCHEDULED after the property drawer; the planner
still reads those, and they can be fixed once with:
#+begin_src sh
docker compose exec emacs emacsclient -s sem-server \
  -e '(sem-core-repair-planning-lines "/data/tasks/tasks.org")'
#+end_src

** LLM provider
- =LLM_PROVIDER=: =deepseek= (default) or =openrouter= (legacy, for rollback).
- =DEEPSEEK_API_KEY= (or the generic =LLM_API_KEY=).
- =LLM_MODEL= (medium tier: URL capture, RSS digest, planning, daily plan) and
  =LLM_WEAK_MODEL= (Pass 1 task normalization; falls back to =LLM_MODEL=).
- =LLM_REASONING_EFFORT= / =LLM_WEAK_REASONING_EFFORT=: =none= (default,
  thinking disabled), =low=, =high= or =max=. DeepSeek thinks at =high= by
  default, which can take minutes for these bounded transformations.

** Path contract
=/data= is split so that WebDAV clients (Orgzly, organice) can only reach
tasks and settings; knowledge files live in the git repository.

#+begin_example
/data/tasks/      WebDAV root: inbox-mobile.org, tasks.org, rec-tasks.org,
                  rules.org, feeds.org, prompts/, errors.org
/data/org-roam/   git repository: org-files/ (org-roam notes), notes/,
                  journal/YYYY-MM.org, digest/ (+ digest/archive/YYYY-MM/)
/data/            daemon internals: sem-log.org, elfeed/, cursor files
#+end_example

- :journal: captures are appended to the current month's
  =journal/YYYY-MM.org=; older months can be edited freely.
- A legacy flat =/data= is migrated automatically at daemon startup
  (=sem-migrate.el=): idempotent, never overwrites, logs conflicts, and keeps
  the original =journal.org= under =/data/.migrated/=.

** org-roam flow
- Link captures become org-roam nodes under =/data/org-roam/org-files=.
- Git sync operates at repository root =/data/org-roam=.
- Keep DB artifacts out of content history (for example =org-roam.db=).

** WebDAV settings
- WebDAV endpoint is your HTTPS domain (for example =https://org.example.com/=).
- Self-hosted organice endpoint uses a dedicated HTTPS origin (for example
  =https://organice.example.com/=).
- Required env values include:
  - =WEBDAV_DOMAIN=
  - =ORGANICE_DOMAIN=
  - =ORGANICE_ORIGIN= (must exactly match =https://ORGANICE_DOMAIN=)
  - =ORGANICE_IMAGE= (optional; defaults to =twohundredok/organice:5826=)
  - =WEBDAV_USERNAME=
  - =WEBDAV_PASSWORD=
- Mobile sync should target the correct path scope (root for inbox/tasks/rules,
  and org-roam subtree as needed).

** Self-hosted orgnote server
- Optional sync server for notes (graph, notes, journal, digests) used by the
  orgnote apps and =orgnote-cli=. Enabled with =COMPOSE_PROFILES=orgnote= and
  the =ORGNOTE_*= variables in =.env=.
- Services: =orgnote-backend= (built from a pinned upstream commit),
  =orgnote-mongo= (MongoDB 5, needs AVX), =orgnote-s3= (SeaweedFS as S3).
- Apache serves only the API on =ORGNOTE_DOMAIN=: clients use
  =https://ORGNOTE_DOMAIN/api/v1= as the server address. No web client is
  hosted.
- Login is GitHub OAuth; the OAuth app callback URL is
  =https://ORGNOTE_DOMAIN/api/v1/auth/github/callback=.
- Clients: the orgnote apps have no server field yet; set it in
  =.orgnote/config.toml= of the notes folder:
  #+begin_src toml
  [network]
  apiUrl = "https://ORGNOTE_DOMAIN/api/v1"
  [synchronization]
  type = "api"
  #+end_src
- Daemon sync: with =ORGNOTE_API_TOKEN= set (an API token created in the
  app), the 5-minute cron cycle runs git pre-pull, refreshes read-only copies
  of =tasks.org= / =rec-tasks.org= in =org-roam/sem/=, then =orgnote-cli sync=
  of =/data/org-roam= (log: =logs/orgnote-cli.log=). New =*.sync-conflict-*=
  files become TODOs in =errors.org=. =digest/archive/= stays in git but is
  not published to orgnote. =sem/= and =.orgnote/= are kept out of
  git via =.git/info/exclude=.

** Self-hosted organice and CORS
- Organice runs as a dedicated container image and is served through the existing
  HTTPS WebDAV container as reverse proxy, routed by host header to
  =ORGANICE_DOMAIN=.
- Browser CORS access is strict single-origin: only =ORGANICE_ORIGIN= is
  allowed, with credentialed requests enabled for that origin.
- Wildcard origins are not used. Disallowed origins are not granted
  =Access-Control-Allow-Origin=.
- =OPTIONS= preflight is unauthenticated for browser compatibility, while
  non-=OPTIONS= WebDAV methods remain authenticated.

** org-ui (own web UI, next to organice)
- Static SPA in =org-ui/= (Vite + React + FullCalendar), served by the WebDAV
  vhost at =https://WEBDAV_DOMAIN/ui/=: same origin as WebDAV, so no extra
  domain, certificate or CORS. organice keeps working unchanged.
- Login works like organice (WebDAV URL, user, password kept in the
  browser's localStorage). =/ui/= itself is public static files and is not
  writable: DAV is enabled on =<Directory "/data/tasks">= only.
- Every write uses =If-Match= (inbox: append only, retried on =412=); captures
  that cannot be sent wait in a local outbox.
- Build: =cd org-ui && npm ci && npm run build= (or in a =node:22= container);
  compose mounts =./org-ui/dist= at =/usr/local/apache2/ui=. Runtime settings
  live in =org-ui/dist/config.json= (source: =org-ui/public/config.json=).
- Tests: =npm test= (unit), =npm run e2e= (Playwright against a local
  Apache started from the production vhost template; needs =apache2=).

** Dual-domain TLS and rollout sequence
1. Configure DNS for both =WEBDAV_DOMAIN= and =ORGANICE_DOMAIN= to point to the
   same host.
2. Issue certificates for both domains via certbot profile:
   #+begin_src sh
   docker compose --profile certbot up -d certbot
   #+end_src
   =CERTBOT_STAGING= only affects the first issuance of a lineage; renewals
   always use the CA recorded in the lineage, so a staging flag left on cannot
   replace a production certificate. The renewal loop warns when a lineage
   still uses the staging CA.
3. Confirm certificate files exist for both lineages under
   =/etc/letsencrypt/live/$DOMAIN/{fullchain.pem,privkey.pem}=.
4. Deploy WebDAV + organice endpoint:
   #+begin_src sh
   docker compose up -d webdav emacs
   #+end_src
5. Verify browser origin flow:
   - allowed origin sends and receives credentialed CORS headers
   - disallowed origins do not receive granted CORS headers
   - unauthenticated non-=OPTIONS= methods still return =401=

Rollback (minimal downtime):
- Keep WebDAV container running until old policy or host route is ready.
- Revert =ORGANICE_*= env values and Apache template changes, then restart only
  the =webdav= service first, followed by dependent services if needed.
- Certbot can continue managing existing lineages; no extra certbot container is
  required for dual-domain renewal.

** Git settings
- SSH key expected by git-sync in container: =/root/.ssh/id_rsa=.
- Git identity must be configured in container (name/email) for commits.
- Manual trigger for inbox processing:
  #+begin_src sh
  docker compose exec emacs emacsclient -s sem-server -e "(sem-core-process-inbox)"
  #+end_src
- Manual trigger for git commit+push:
  #+begin_src sh
  docker compose exec emacs emacsclient -s sem-server -e "(sem-git-sync-org-roam)"
  #+end_src

* Security
Security model is "LLM as untrusted component".

** Sensitive blocks
- Text inside =#+begin_sensitive= / =#+end_sensitive= is not sent to the LLM.
- Sensitive payload is masked before model calls and restored afterward.

** Planner context
- The planner and the daily plan receive task titles, categories, priorities,
  efforts and timestamps of open tasks within a 14-day window. Task bodies are
  not sent to the planner; the daily plan sends a short body excerpt with
  sensitive blocks removed.
- Titles are already sent to the same provider during task normalization, so
  hiding them from planning protected little while making scheduling blind.

** Trust boundaries
- LLM output is treated as untrusted text and validated before acceptance.
- Deterministic code paths handle retries, DLQ/error logging, file writes, and
  cron overlap guards.
- Operational data stays in plain files you can inspect directly.
